# アイコン・イラスト素材の調達（絵文字を使わない）

`case-icon` やバッジ、tint-boxの先頭記号などに絵文字（📄✅💡など）をそのまま
使うと、デフォルトの色（黄色い月、緑のチェック等）がmono配色の「差し色1色」
ルールと衝突し、資料全体が安っぽく見える。**絵文字は使わず、必ず外部アイコン
素材に置き換える。** ユーザーから「絵文字はダサさが出る」と明示的な指摘を受けて
確立した方針。

このファイルは3種類の素材を扱う：**1. ブランドロゴ**（実在サービス名を出すとき）
**2. 汎用アイコン**（バッジ・箇条書きの先頭記号など）**3. 場面・感情を表すイラスト**
（文字量が少なく余白の余るスライドの装飾）。

## 1. サービス／ブランドのロゴアイコン → LobeHub Icons / svgl.app

Claude・ChatGPT・Gemini・Notionなど**実在サービスのロゴ**は
[LobeHub Icons](https://lobehub.com/ja/icons)（例：https://lobehub.com/ja/icons/claude ）
からSVGをダウンロードして使う。各サービスのブランドカラー付きアイコン（`claude-color.svg`
等）と、単色のシンプル版がある。ユーザーが該当サービスのアイコンをDownloadsに
保存してくれることが多いので、まずそちらを探す（`find Downloads -iname "*サービス名*"`）。
既存のダウンロード画像がロゴの一部を切り抜いた不正確なもの（スクリーンショット等）
だった場合は、LobeHubの正式なSVGに差し替えるようユーザーに提案してよい。

LobeHubに無いサービスや、モノクロ／カラー両バージョンを比較したい場合は
[svgl.app](https://svgl.app/)（開発者ツール・SaaS系のロゴが豊富）も候補にする。
svgl.appは**公開APIで直接SVGをcurl取得できる**ので、サイトをブラウザで開く
必要はない（Iconifyと同じ「APIから直接ダウンロード」方式）。

```bash
# 一覧JSON（title・category・SVGの直リンクを含む）を取得して該当ロゴを探す
curl -s "https://api.svgl.app" -o /tmp/svgl.json
# JSON中の "route" (または route.light/route.dark) が実SVGの直URL
# 例: https://svgl.app/library/langchain-logo.svg
curl -s "https://svgl.app/library/{ファイル名}.svg" -o "shots/icons/{name}.svg"
```

- ロゴによっては `route` が単一URLではなく `{light: ..., dark: ...}` のオブジェクトになっている（配色に合わせて選ぶ）。ワードマーク付き版がある場合は `wordmark.light`/`wordmark.dark` も別途取得できる。
- ダウンロード後はLobeHub素材と同様にアスペクト比を確認し、`object-fit: contain` か `width` のみ指定にする。

- ロゴがワードマーク込み（文字入り）か、アイコンのみかを確認する。アイコンのみの
  場合は、UI側で必ずサービス名のテキストラベルを添える（アイコンだけでは何の
  サービスか伝わらない）。
- 画像の実寸アスペクト比を確認してから使う（`PIL.Image.open(...).size`）。正方形で
  ない画像に `width:Npx; height:Npx` を両方指定すると引き伸ばされて歪む。正方形で
  ない場合は `object-fit: contain` を使うか、`width` のみ指定して `height: auto` にする。

### SVGはbase64にせず、インラインで直接貼る

PNG等のラスター画像は`<img src="data:image/png;base64,...">`で埋め込む（単体HTML
方針のため、これは変えない）。だが**SVGはXML＝テキストなので、base64化する必然性
がない。** base64にすると元サイズの約1.33倍に膨張する上、ソースも読めなくなる。
SVGファイルの中身（`<svg>...</svg>`）をそのままHTMLに貼り付ける「インラインSVG」
の方が軽量で、`fill="currentColor"`にしておけばCSSで後から色を制御することもできる
（ブランドロゴは公式配色を保つのが基本なのでこの恩恵は薄いが、汎用アイコン
（Iconifyのlucideセット等）では有効）。

```python
# ダウンロードしたSVGファイルの中身をそのまま文字列として読み込み、
# base64化せずにHTMLへ埋め込む
with open('claude.svg', encoding='utf-8') as f:
    svg_markup = f.read()
# svg_markup をそのまま <span class="ico">{svg_markup}</span> のように配置する
```

PNG/JPGなど元からラスター形式の画像には、この手段は使えない（base64一択）。

## 2. 汎用アイコン（フォルダ・チェック・虫眼鏡など）→ Iconify API（lucideセット）

サービスに紐付かない汎用アイコン（before/after・チェック・検索・カレンダー等）は
[Iconify](https://iconify.design/) の公開APIから `lucide` アイコンセットを取得する。
ネットワーク接続があれば以下のコマンドで直接SVGファイルをダウンロードできる
（アカウント登録・APIキー不要）：

```bash
curl -s "https://api.iconify.design/lucide:{アイコン名}.svg?color=%23{HEXカラー（#なし）}" \
  -o "shots/icons/{アイコン名}-{用途}.svg"
```

- 色は取得時にクエリパラメータで焼き込む（`color=%2317160F` のように `#` を `%23`
  に変換する）。`currentColor` のまま埋め込んで後からCSSで制御しようとすると、
  `<img>` タグ経由の読み込みでは色が継承されず失敗するので、**取得時点で最終的に
  使う色（`--mono-ink` か `--mono-accent` の16進値）を指定してダウンロードする**。
  同じアイコンを両方の色で使いたい場合は2回ダウンロードして
  `{name}-ink.svg` / `{name}-accent.svg` のように保存し分ける。
- アイコン名は [lucide.dev](https://lucide.dev/icons/) で検索して確認する（例：
  `folder-open`, `circle-check-big`, `handshake`, `search`, `moon`, `map-pin`,
  `calendar`, `users`, `building-2`, `landmark`, `smile`）。
- ダウンロード後、`wc -c` でファイルサイズが100バイト未満でないか（＝404エラー
  ページを保存していないか）を必ず確認する。

## 3. 場面・感情を表すイラスト → Loose Drawing

タイトルページ・セクション区切りページ・まとめページなど、**文字量が少なく右半分
などに余白が余るスライド**には、アイコンではなく人物・場面イラストを入れると
資料の印象が良くなる。[Loose Drawing](https://loosedrawing.com/) は商用利用可・
線画＋カラー展開（赤/緑/青/黄/黒）のイラスト素材サイト。

- **サイト自体がBrowserペインのポリシーでブロックされ、直接開いて閲覧・ダウンロード
  することはできない。** また画像のダウンロードはそもそもユーザー承認が要る操作
  なので、代行取得は狙わない。
- 実務上の流れ：
  1. 空いているスライドを見つけたら、`.illust-placeholder`（破線枠、後述CSS）で
     「イラスト差し込み予定」の仮置きをしておき、**具体的な検索キーワードと色**
     （例：「ゴール・旗・登る／青系統」）をプレースホルダー内に明記してユーザーに提示する。
     スライドの内容に合わせて毎回キーワードを変える（「学ぶ・本」「作る・工作」
     「紹介・共有」「歯車・仕組み」「虫眼鏡・調べる」「ロボット・AI」「お土産・
     持ち帰る」など）。
  2. ユーザーがLoose DrawingでPNGをダウンロードしてくれるので、`find Downloads
     -newermt "-N分"` 等で直近ダウンロードされた画像を検出し、`Read` で内容を確認して
     どのプレースホルダーに対応するか判断する（ファイル名は連番でヒントにならない
     ことが多いので、必ず画像の中身を見て判断する）。
  3. 取得したPNGは `base64.b64encode` でbase64化し、`<img src="data:image/png;base64,...">`
     として直接HTMLに埋め込む（単体HTML方針を維持し、外部ファイル参照にしない）。
  4. 差し込んだら `.illust-placeholder` の破線枠・案内文は削除し、素の `<img>` に
     置き換える。
- Loose Drawingは紫寄りの青（#7B6FEE前後）で塗られていることが多いが、mono-slide-pdfの
  差し色（`--mono-accent`）と完全一致していなくても許容範囲。線画がメインで色面は
  アクセント程度なので、資料全体の配色を大きく崩さない。

```python
# base64埋め込みの例
import base64
with open('ダウンロードした画像.png', 'rb') as f:
    b64 = base64.b64encode(f.read()).decode()
img_tag = f'<img src="data:image/png;base64,{b64}" style="max-width:100%; max-height:100%; object-fit:contain;">'
```

```css
.illust-placeholder {
  border: 2px dashed var(--mono-faint);
  border-radius: 12px;
  display: flex; align-items: center; justify-content: center;
  color: var(--mono-faint); font-size: 14px; font-weight: 600;
  text-align: center; line-height: 1.7; padding: 16px;
}
```

## 4. イラストの配置パターン（重要：コーナーバッジにしない）

ユーザーから「画像の使い方が違う」と明確な指摘を受けて確立したパターン。**タイトルや
見出しの右上に小さく（100〜130px角）アイコンを置く「コーナーバッジ」方式は使わない。**
情報がすでに詰まっているスライドに小さく足すと装飾ノイズにしかならない。

正しいパターンは、**文字量が少なく余白の多いスライドを`.content`ごと左右2カラムに
分割し、右半分いっぱいにイラストを`object-fit:contain`で敷く**こと：

```html
<div class="content" style="display:flex; gap:28px; align-items:center;">
  <div style="flex:1.2; display:flex; flex-direction:column; justify-content:center;">
    <!-- 見出し・本文・カードなど、通常のテキストコンテンツ -->
  </div>
  <div style="flex:1; display:flex; align-items:center; justify-content:center;">
    <img src="data:image/png;base64,..." style="max-width:100%; max-height:320px; object-fit:contain;" alt="illustration">
  </div>
</div>
```

- 対象は「見出し＋一言だけ」のような余白の多いスライド（問いかけページ、締めの
  アクションページなど）に限る。カード3〜4枚で埋まっているスライドには使わない。
- **タイトルページ（表紙）には画像を置かない。** 参考にした社内セミナー資料でも
  表紙は文字のみで統一されていた。
- 使う画像が見つからない/弱そうな場合は、無理に全スライドに敷き詰めず、
  テキストだけのスライドとして残す方が資料全体の統一感が保たれる。

## 4.5 操作手順の説明には実写スクリーンショットを使う

「Googleドライブの検索バーで探す」「仕様書をダウンロードする」のような**具体的な
UI操作の手順**を説明するスライドには、Loose Drawing等の抽象イラストではなく、
**ユーザーが実際に撮ったその場面のスクリーンショット**を使う。抽象イラストは
「気持ち・場面」を表すには良いが、実際の画面操作の説明には向かない。

- ユーザーが「スクリーンショットを撮った」と言ったら `find Downloads -newermt
  "-N分" \( -iname "*.png" -o -iname "*.jpg" \)` 等で直近の画像を探す。
- 複数枚ある場合は全部 `Read` で中身を確認してから、どの手順のどのステップに
  対応するか（検索画面／結果一覧／ダウンロード画面／中身、など）を判断する。
  ファイル名（スクリーンショット_日時.png）はヒントにならないことが多い。
- 実写スクショは画面全体で情報量が多いので、上記の半分カラムパターンに載せる
  ときは `max-height` を実測してから決める（縦長スクショは特にはみ出しやすい。
  `max-height:280〜300px; object-fit:contain` を目安に、必ずJSのoverflow
  チェックで確認する）。
- 手順が3〜4ステップある場合、1スライドに詰め込まず「前半2ステップ／後半2ステップ」
  のように2枚に分けると、画像1枚あたりのサイズを確保しやすい。

## 5. アイコンの使い方の原則

- `case-icon` の中身は絵文字テキストではなく `<img class="ico" src="shots/icons/xxx.svg"
  style="width:Npx;height:Npx;">` にする。サイズは元の絵文字フォントサイズと同じ
  px値をそのまま流用すれば大きさの調整は不要なことが多い。
- 差し色（`--mono-accent`）を使ってよいのは、`case-highlight` の中のアイコンや、
  警告・強調のためのアイコン（`triangle-alert` 等）だけ。それ以外は `--mono-ink`
  （黒系）で統一し、色のバラつきで資料が騒がしくならないようにする。
- ネットワーク接続が使えない環境では、Iconify取得の代わりにLobeHub/ユーザー提供
  画像で代替するか、取得済みの `shots/icons/` 配下を使い回す。
